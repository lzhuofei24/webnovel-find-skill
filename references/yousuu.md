# 书评数据库扫描

书评平台备份可以把模糊找书转化为可枚举的候选筛选，但任何单一备份都有时间、作品和评论覆盖缺口。使用前重新核对来源、许可证、访问条件、文件结构和数据更新时间；只使用公开且合规可访问的数据，不将数据库文件放入 skill 包或公开仓库。

## 数据准备

优先寻找包含以下字段的公开书目数据：作品 ID、书名、作者、原始分类或标签、简介、目录链接、状态和字数。评论数据至少需要作品 ID、评论 ID、正文和时间。不同来源的 ID 规则可能不同，必须从实际字段或 URL 证实连接关系；不要按 CSV 行号猜测关联。

解压前列出归档目录，确认路径不会写出目标目录。读取 SQLite 时使用只读连接。保存来源 URL、获取日期、schema、原始计数和已知缺口，供最终结果说明。

合并多个来源时，优先使用稳定作品 ID；ID 相同但书名或作者冲突要标记冲突。ID 不通用时，用规范化的“书名＋作者”暂时合并，并保留每个来源的原始记录。相同评论在跨库出现时按规范化正文哈希去重，同一文本的副本不增加证据强度。

## 扫描器

scripts/scan_reviews.py 只使用 Python 标准库，读取 SQLite 或 CSV，输出 candidates.json 与 coverage.json。字段变化时应显式失败并先调整适配，不要静默丢弃记录。

运行格式：

    python <skill-path>/scripts/scan_reviews.py --sqlite <database.sqlite> --old-dir <csv-directory> --config <clues.json> --out <output-directory>

clues 是线索列表。每个线索有 id、weight 和 groups；同一线索内所有正则都要匹配同一条文本，各正则可用 | 表示同义词。candidate_when 是“任一规则满足即可入选”，每条规则中的所有线索必须在同一本书中出现。权重每条线索只计一次，避免热门书因评论多而虚高。

下面只说明配置格式。应根据当前用户的记忆重写关键词和近义表达，不把示例当作固定剧情。

    {"clues":[{"id":"罕见能力","weight":12,"groups":["印记|花纹|胎记","分身|化身|九个"]},{"id":"关系线索","weight":10,"groups":["姑侄|姨甥|亲属","老师|导师"]},{"id":"题材线索","weight":2,"groups":["星际|宇宙|未来|虫族"]}],"candidate_when":[["罕见能力"],["关系线索"],["关系线索","题材线索"]]}

扫描结果只表示评论或元数据出现了相关词。评论可能是在否定、比较其他作品、转述书单或泛指题材，因此必须回到目录、章节或可靠原文来源逐项核验。
