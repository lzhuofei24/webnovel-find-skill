# Webnovel Finder Skill

一个根据剧情记忆寻找网络小说书名的 Codex skill。

它适合这些场景：记得若干剧情片段、人物关系、能力设定或阅读年代，但忘记了书名；希望从大量候选中筛选，而不是只依赖搜索引擎碰运气。

## 核心方法

```text
寻找覆盖较大的书目、标签或书评数据
            ↓
建立可枚举的候选书单
            ↓
按题材、标签和剧情线索筛选并排序
            ↓
逐本核对简介、目录、评论和正文
            ↓
用多组独立情节确认书名
```

公开搜索主要用于发现数据源、补充候选、定位目录或正文，以及核对候选书。搜索引擎没有结果，不代表作品不存在。

## 目录

- `SKILL.md`：完整的找书流程、容错规则和证据标准。
- `references/yousuu.md`：书评数据库的准备、合并和扫描方法。
- `scripts/scan_reviews.py`：读取 SQLite 或 CSV 书评数据并生成候选结果。
- `agents/openai.yaml`：Codex 界面显示信息。

## 扫描评论数据

扫描器只使用 Python 标准库。准备一个线索配置文件后运行：

```powershell
python scripts/scan_reviews.py `
  --sqlite path/to/database.sqlite `
  --old-dir path/to/csv-directory `
  --config clues.json `
  --out output
```

`--sqlite` 和 `--old-dir` 至少提供一个。输出目录包含：

- `candidates.json`：按线索命中分数排序的候选书和证据片段。
- `coverage.json`：原始记录数、合并数量、候选数量、冲突和配置摘要。

示例配置：

```json
{
  "clues": [
    {"id": "罕见能力", "weight": 12, "groups": ["印记|花纹|胎记", "分身|化身|九个"]},
    {"id": "关系线索", "weight": 10, "groups": ["姑侄|姨甥|亲属", "老师|导师"]},
    {"id": "题材线索", "weight": 2, "groups": ["星际|宇宙|未来|虫族"]}
  ],
  "candidate_when": [
    ["罕见能力"],
    ["关系线索"],
    ["关系线索", "题材线索"]
  ]
}
```

同一线索的正则需要命中同一条文本；`candidate_when` 中任意一条规则满足即可入选。扫描结果是排序依据，不是剧情证明，必须继续查看目录、章节或可靠原文。

## 证据边界

- 至少三组相互独立的关键情节得到支持，才适合确认书名。
- 书评、搜索摘要和转载内容可以帮助定位，但不能自动等同于正文证据。
- 用户求助帖、同一帖子的转载和跨库重复评论不算独立证据。
- 年份、章数、分类、称谓和平台可能因记忆偏差、合章、拆章或改名而变化。
- 不绕过登录、付费墙或验证码，不把数据库文件和个人搜索记录放入仓库。
